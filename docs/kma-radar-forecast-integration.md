# 기상청 레이더 강수예측 영상 연동 검토 (아직 개발·승인 검증 전)

## 실제 확인된 공식 엔드포인트

기상청 API허브 레이더: https://apihub.kma.go.kr/apiList.do?seqApi=5

- **레이더 합성 관측영상**: `/api/typ04/url/rdr_cmp_file.php` with `data=img&cmp=cmb`. 전국 합성 관측영상으로, 미래 예측이 아님. 공식 설명상 10분 간격 자료.
- **초단기 강수예측 분포도(지도 배경 포함 가능)**: `/api/typ03/cgi/rdr/nph-qpf_ana_img`; 명세 예: `qpf=M&ef=60&map=HR&legend=1`. 기상청 API허브 레이더 문서의 3.4.
- **배경지도 없는 레이더 1시간 예측영상(최우선 검토)**: `/api/typ03/cgi/rdr/nph-qpf_ana_imgp`; 예: `PROJ=LCC&obs=qpf&qcd=EXT&qpf=M&ef=60` + 공식 필수 이미지/투영/시간/영역 설정. 명세의 4.4.
- 위 `imgp` 유형은 공식적으로 투영법·이미지 파일 경로 등을 JSON으로 반환한다고 설명하며, 이미지 파일 경로는 기상청 API허브 도메인을 기준으로 접근하도록 안내. 실제 응답 구조와 위경도 경계는 계정 승인 후 반드시 검증.

## 권장 Sunny SAI 구현

1. 기상청 API허브에서 위 두 레이더 강수예측 API에 **각각 활용신청** 후 기존 서버 전용 환경변수 `KMA_API_KEY`로 허용되는지 확인. 기존 예보 API 성공 != 레이더 활용승인 성공.
2. 서버가 허용된 호스트·정해진 인자만 요청하고 이미지·메타데이터를 중계. 키를 클라이언트에 노출하지 않음. 응답 크기와 MIME, 실제 유효·발표시각, 요청 제한, 캐시를 검증.
3. 반사도/예측값 영상의 투영 좌표 LCC 등을 근거로 원본 지리참조를 검사하고 WGS84 또는 웹지도 타일 좌표계에 정확히 변환. 원본 영상에 이미 지도가 포함되어 있으면 위치 정합이 어려울 수 있으므로 **배경지도 없는 이미지**를 우선 검토. 지상 통과점 3~4개로 화면상의 정합 검증.
4. 카카오 지도 위에는 **Geo-registered raster/tile overlay**를 구현해야 함. Kakao JS API에 특정 Google Maps `GroundOverlay`가 있다고 가정하지 말 것. 서버에서 EPSG:3857 타일로 사전 정합하고 실제 지도 투영·확대·이동과 동기화되는 오버레이로 렌더링.
5. 이용자가 선택한 예측 유효시각에 해당하는 실제 프레임만 재생: 관측 과거 → 0~예측 시간 프레임, 시각/출처/예보임을 명확하게 표시. 없으면 프레임을 생략하고 데이터 없음 표시. 지도 회전 중 정합도 별도 검증.
6. 기존 기상청 `RN1` 5km 소수 표본은 경로 위치 수치·알림에 유지하고, **레이더 강수예측 영상은 별도 시간 애니메이션 지도층**으로 배치. 레이더 관측과 레이더 예측 명칭을 반드시 분리.
7. 프리뷰에서 API 승인·이용조건·응답·시간 6프레임 이상·좌표 정합·모바일 성능 검증이 모두 통과하기 전에는 레이어 버튼을 활성화하지 않음. GIF로 임의 이동시키는 효과는 사용하지 않음.
