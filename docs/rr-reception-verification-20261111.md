# RR 원본 수신·값 검증 — 2026-11-11

## 결론

RR NC 원본 수신에 성공했다. 초기 실패는 KO·EA 조회에서 발생했고, ELA 확장영역을 추가 조회하자 실제 RR 파일이 수신됐다. 이로써 RR·CI·FOG 3종 모두 NC 수신 근거가 확보됐다. 실제 카카오맵 중첩과 운영 위험판단 엔진 입력은 아직 연결하지 않았다.

## 실제 시험

고정 프리뷰·운영을 변경하지 않고 동일 프로젝트의 임시 프리뷰에서 등록된 기상청 키로 검사했다.

1. `sat_meta_list.php`는 RR의 apiNc=O, KO·EA 제공, ELA 미제공으로 안내했다.
2. 신규 NC 목록을 KO 기본/LC, EA 기본/LC/GE, ELA LC로 조회했다. 앞의 다섯 조합은 비었지만 ELA LC는 154개 관측시각을 반환했다(검사 시점 2026-11-11 05:11 UTC).
3. KO·EA는 실제 영상 시각 및 인접 10분 시각으로 다운로드해도 파일 없음이었다.
4. ELA LC의 실제 NC 목록에 있는 2026-11-11 05:08 UTC 파일을 다운로드했다.

성공 요청(인증키 제외):

```
https://apihub.kma.go.kr/api/typ01/url/sat_file_nc_down.php?lvl=l2&data=rr&area=ela&map=LC&tm=202611110508
```

목록은 `sat_file_data_list.php`에 동일한 data/area/map과 type=nc, tm=20261111을 사용했다. 관측시각은 목록에서 얻었으며 파일명을 임의로 만들지 않았다.

## 파일을 실제로 열어 확인한 내용

- 855,743바이트 HDF5/NetCDF4
- title: AMI L2 RR
- algorithm_version: GK2A_RR_v1.2021.01.4
- processing_area / observation_mode: ELA
- 변수: RR, Raining_CT_flag
- 배열: 1200×1900
- RR 원본형식: uint16, 단위 mm/h, 유효 범위 0~10000, 결측 65535
- scale_factor: 0.009999999776482582, add_offset: 0
- Raining_CT_flag는 강수 구름 유형이다. FOG의 품질코드나 CI의 이전 객체 플래그로 해석하면 안 된다. 코드 0의 상세 의미는 제공 속성에서 설명되지 않았으므로 임의의 품질등급을 부여하지 않는다.

수신 표본은 결측 0개, 유효값 2,280,000개, 원본값 범위 0~9832, 원본값 0은 2,011,394개였다. 값 0은 해당 격자의 위성 추정 강수 0이며, 도로 안전을 보증하지 않는다.

## 공식 격자 API와 원본 대조

동일 시각의 RR 배열 [row=667, column=1233]은 원본값 9832였다. 공식 격자 조회에 ix=1234, iy=668, var=RR을 넣으면 `9.83200e+03`을 반환했다. 즉 격자 API 값도 이미 mm/h로 변환된 값이 아니라 이 경우 NC의 저장값이었다.

올바른 변환은 9832×scale_factor+add_offset ≈ 98.32mm/h이다. 배율을 생략하거나 두 번 적용하면 안 된다. 이 수치는 원본/API의 일치 검증용이며 사용자의 경로 위험 판정이 아니다.

## 좌표

RR의 projection, 원점경도, 위성높이, 장·단반경, 스캔 계수, 오프셋은 앞서 전체 공식 격자로 검증한 CI 원본과 정확히 일치했다. 요청에 map=LC가 있어도 실제 원본은 geostationary였다. `public/gk2a-ci-navigation.mjs`의 검증된 ELA GEOS 변환을 재사용할 수 있다.

## 코드 변경

- 기본 RR 수치 진단의 요청 영역을 실제 수신한 ELA LC로 수정했다.
- RR 격자값에 packed 값임을 표시하고 배율·결측·단위 정보를 첨부했다.
- 원본값 변환과 결측·구름유형 처리를 별도 함수로 만들었다. 도로 침수 확정이나 자동 우회 신호는 생성하지 않는다.
- 반복 진단은 고정된 공식 엔드포인트·제품·영역만 사용하며 인증키나 기관 오류 본문을 결과에 출력하지 않는다.

공식 제공영역 안내와 실제 동작의 차이는 향후 API 변경 시 재확인해야 한다. 현재 성공한 조합을 기준으로 사용한다.
