# Sunny SAI — ITS / TAAS 위험정보 연동 (2026-11-10)

## 현재 구현
- 서버 전용 `ROAD_API_KEY`로 ITS `eventInfo`, `trafficInfo`를 같은 국내 자동차 경로의 좌표 외접범위에서 조회한다.
- `POST /api/its-route-context`는 같은 출처 세션 및 CSRF, 국내 2~24 좌표, rate limit을 요구한다. 브라우저에 키를 반환하지 않는다.
- `public/its-route-risk.mjs`는 실제 카카오 차량 경로의 좌표/통과시각과 ITS 사건 지점을 비교한다. 경로 120m 이내이고 기관 발생시각이 확인된 최근 24시간 사건만 **경로 인접 주의정보**로 사용한다. 같은 도로 링크/방향은 미검증이며 자동 우회는 하지 않는다.
- 소통정보는 링크 ID와 속도의 건수만 진단한다. 전국 표준노드링크 지오메트리 및 현재 경로와 대조하기 전까지 해당 경로의 정체/속도라고 단정하지 않는다.
- 표출 메뉴의 `ITS 사고·공사·통제` 스위치는 실제 자동차 경로 및 ROAD 인증 설정 시 활성화되며, 시연용 사고 데이터를 실시간 ITS 정보로 위장하지 않는다.

## TAAS 승인 자료
- `KOROAD_API_KEY`의 WMS 승인과 REST 승인은 별개의 데이터 상품일 수 있다. 기존 보행자 `REST /frequentzone/pedstrians`는 프리뷰에서 정상 결과가 확인되지 않았으므로 위험점수 0/안전으로 해석하면 안 된다.
- `GET /api/taas-approved-diagnostic`: **Vercel Preview에서만**, 인자 없는 고정 시험. 2024년 서울 중구 보행자 사고다발 WMS PNG 수신과 경부고속도로 판교IC–신갈JC 승용차 위험지수 REST 응답을 각각 구분한다. 이 진단은 실제 경로의 안전성 검사가 아니다.
- TAAS WMS는 PNG 지도 레이어, REST는 수치/공간 데이터를 제공한다. WMS PNG의 각 픽셀에서 공식 사고건수, 실시간 사고위험, 도로 통제 정보를 추출한다고 가정하지 않는다.
- 도로위험지수 `anals_grd` 01–04는 코드 검증 전 숫자만 진단하고, 같은 노선명/구간 및 좌표로 검증 전에는 운전자 위험 등급으로 노출하지 않는다.

## 남은 검증
1. 배포 한도가 초기화된 뒤, 사용자 요청 시 **고정 프리뷰에만** 이 개발 브랜치 최신 커밋을 배포한다. 운영(main)은 그대로 둔다.
2. `POST /api/its-route-context` 실제 발급키 응답: HTTP 상태, response 구조, 이벤트 위치·시각, 속도 링크, 응답 건수 확인. 원문 응답이나 키는 로그에 남기지 않는다.
3. `GET /api/taas-approved-diagnostic` 실제 WMS PNG와 REST 수치 응답. REST 미승인 시 보행자 사고 레이어는 오판하지 않도록 미수신으로 유지한다.
4. 서울시청→부산시청 카카오 자동차 경로와 ITS 신고 지점의 인접성 지도 확인. 같은 도로 링크·진행방향·통제 범위는 추가적으로 확인해야 한다.
5. 서울역→서울시청 TMAP 도보 경로의 사고다발지역 REST는 신청 범위/응답구조 수정 후 재검사한다.
6. GPS/지도 회전/음성/모바일 UI는 별도의 실제 브라우저·기기 E2E 검증이 필요하다.

## 공식 API 문서
- ITS: https://www.its.go.kr/opendata/opendataList
- TAAS WMS: https://opendata.koroad.or.kr/api/selectPedstriansWms.do
- TAAS 고속도로 REST: https://opendata.koroad.or.kr/api/selectHighwayDataSet.do
