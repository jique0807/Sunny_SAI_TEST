# Sunny SAI 모듈형 위험판단·데이터 연결 구조

## 설계 목표

**특정 상용 LLM·단일 데이터 공급자에 의존하지 않는** 설명 가능한 경로 위험판단. 모델·입력 소스 교체 시에도 동일한 입력 검증, 수신 상태, 위치 정합, 시각, 결측 구분, 위험결정 보류 계약을 유지한다. 이 문서는 실행 가능한 인터페이스와 아직 미구현 영역을 분리한다.

### 처리 파이프라인

실제 자동차 Kakao/도보 TMAP 경로 → 경로 형상·출발시각·구간별 ETA 검증 → KMA/ITS/TAAS 등 공급기관 수집 → 기관 인증/형식 검증 → 지리좌표·발생/발표/유효시각 정합 → Risk Engine 2.0 검증 위험신호 → 정책어댑터 선택 → 지도·위험바·음성 안내. 시연용 입력은 실제 위험판단과 분리된다. 표출 스위치 OFF가 위험자료 수집 OFF라는 의미가 아니다.

### 입력자료 교체 및 확장

1. \`lib/capability-catalog.mjs\`의 \`SOURCE_ADAPTERS\`에 어댑터 ID, 슬롯, **키 이름만**, 서버 라우트, 역할을 선언한다. \`GET /api/capability-catalog\`는 로그인 세션 쿠키를 확인한 후 이 목록을 안전하게 반환한다.
2. 공급자마다 서버 측 호스트·경로·타입 허용 목록을 고정하고 네트워크 실패·429·인증 실패·자료 없음·시간초과를 명확히 구별한다. 브라우저에서 임의 API URL이나 운영자 비밀값을 받지 않는다.
3. 공급기관의 원본 자료를 현재의 정합·시간검증 데이터 계약으로 변환하는 **서버 어댑터 코드를 추가**한다. 목록 등록만으로 자동 연결되거나 검증이 완료되는 것이 아니다.
4. 위험 평가에 쓸 때는 KMA처럼 출처/좌표/ETA·예보시각이 일치하는 경우만 승인한다. Open-Meteo는 기상 참고자료로 제공할 수 있으나 현재 Risk Engine 2.0이 KMA 수준의 검증 위험점수로 자동 승격하지 않는다.
5. 실제 기관 API 수신·계정 승인·정합·과거 사례와 실패 사례 시험이 통과한 이후에만 운영에 채택한다.

### 판단정책과 LLM 연결 경계

\`public/risk-model-adapters.mjs\`의 \`createRiskModelRegistry\`는 \`rules-v2\`와 \`rules-v2-strict\`를 실제 실행 가능한 정책으로 제공한다. 후자는 기상표본 100% 미달 또는 미검증 위험신호가 존재하면 **판단 보류**한다. 브라우저 환경설정에서 선택 가능하며, 앱 실행에 외부 LLM이 필요하지 않다.

새로운 정책은 \`registry.register({id, name, refine(profile)})\` 계약으로 주입할 수 있다. \`refine\`은 기존 위험 엔진의 **검증된** 프로파일만 받으며 \`{abstain: boolean}\`만 반환할 수 있다. 어떤 확장 정책도 검증 자료/위험지점/점수/신뢰도를 조작하거나 결측을 '안전'으로 판정하도록 승격할 수 없다. 잘못된 정책 응답이나 예외는 결정 보류로 처리한다.

LLM을 연결할 경우에도 **비권위적인 문장 생성** 계층으로 분리한다. LLM 출력은 구조화된 검증 결과를 해설할 수 있지만 사고 관측값, 도로 폐쇄 여부, 우회로 안전성을 스스로 확정할 수 없다. 현재 외부 LLM 설명 어댑터는 **미연결**이며, 자율 학습/실시간 모델 교체/LLM 경로 탐색은 구현되었다고 주장하지 않는다.

### 자료 흐름 관찰 및 API 운영

\`public/risk-lineage.mjs\`의 \`buildRiskLineage\`는 \`sunny-risk-lineage-v1\` 계약으로 이동수단, 정책, 경로 근거 충족률, 수집 출처별 상태, 제외된 신호 수를 요약한다. 구체 좌표, 쿠키, API 키, 개인 이동이력, 공급기관 원문을 담지 않는다. 환경설정 → **자료 처리 흐름·연결 구성**에서 실제 경로에 대한 요약을 볼 수 있다. 이것은 장기 로그 저장이나 외부 텔레메트리 스트림이 아니다.

API 자격증명은 기존 Vercel 환경변수에서만 등록·교체한다. 환경설정 → 데이터 연결 상태의 실수신 검사는 별도 버튼으로 수행한다. 구성 목록의 \`configured\`는 키 존재만 뜻하며 실수신 성공/자료 정합 확인과 다르다.

### 테스트 및 정직한 미완료 항목

\`test/risk-architecture.test.mjs\`는 키 비노출, 공급기관 구분, 두 정책의 실제 실행과 결측 보류, 외부 정책의 무단 위험 생성 방지, 자료 흐름의 비식별화 및 세션 보호를 검증한다. 종합 CI에서는 기존 \`pnpm check\`, \`pnpm test\`, \`pnpm build:vercel\`도 통과해야 한다.

아직 별도 추가 작업이 필요한 항목: 모든 공급기관에 동일한 데이터 변환 계약 적용, 실시간 모델/어댑터 핫스왑, 복수 실제 후보경로 비교, GK2A 좌표 정합, ITS 기관 실수신 복구, TAAS 지도 시각 검증, 실주행 기기 시험, 운영환경 배포와 실제 수신 검증. 완료되지 않은 검증을 성공으로 표시하지 않는다.
