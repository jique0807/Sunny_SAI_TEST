# Sunny SAI · 차량·도보 경로 기반 기상·위험 안내

2026 공공 AI 대전환 챌린지 **세션1** 제출용 소스입니다.
경로상의 위치·예상 통과시각에 기상·도로·보행 정보를 연결하고, 규칙 기반 엔진이 산출한 판정 근거를 선택 가능한 LLM으로 설명하는 웹앱입니다.

## 1. 접속 주소와 실행물

- 운영: https://sunny-sai-test.vercel.app
- 프리뷰: https://sunny-sai-preview.vercel.app
- 형태: 브라우저에서 실행하는 웹앱/PWA. 별도 EXE·APK·IPA는 포함하지 않습니다.
- 검증된 프리뷰 소스 기준: `2987de9c28819e07684ff1f9e9a3034117297551` (2026-11-11).
- 검증된 프리뷰의 앱 소스를 운영 `main` 브랜치로 통합했습니다. 운영 전용 제출 안내 README는 보존했으며, 운영 배포와 실행 검증 상태는 Vercel에서 확인합니다.

심사 시 위 운영 주소에서 바로 체험하거나, 아래 방법으로 소스를 직접 실행할 수 있습니다. 웹앱 접속은 소스 저장소의 비공개 설정과 별개입니다.

## 2. 주요 기능

| 기능 | 작동 방식 |
| --- | --- |
| 자동차·도보 길찾기 | 자동차는 Kakao Mobility, 도보는 등록된 TMAP 또는 카카오 경로 어댑터 이용 |
| 위치 추적·지도 안내 | 사용자가 허용한 GPS 위치로 경로 진행 상태와 전방 구간 갱신 |
| 기상·위험 자료 표시 | 기상청·교통·보행 자료 어댑터의 자료 수신 결과, 기준시각·결측·출처 표시 |
| 위험판정·우회 후보 | 자동차·도보의 규칙 기반 엔진으로 판정하고 조건에 따른 대안 경로 비교 |
| 판단 근거 설명 | LLM 미사용 / Google Gemini / GPT-OSS / 서버에 등록된 호환 API 선택 |
| 음성 안내 | 브라우저 기본 음성, 선택적인 Google 음성 연결; 지원 환경에 따라 차이 |
| 평가용 시뮬레이션 | 자동차·도보 시연, 출발·목적지 선택형 더미 시나리오와 실행 기록 |
| 데이터 연결 진단 | API 키 설정 상태와 실제 자료 수신 성공 여부를 구분하여 표시 |

모든 자료가 언제나 수신되는 것은 아닙니다. 키 설정·이용권한·호출 한도·공급자 응답에 따라 기능이 제한될 수 있습니다. 과거 사고 통계나 예보를 실시간 사고·현장 통행 상태로 해석하지 않습니다.

## 3. 심사위원용 작동 순서

### 자동차·도보 시연

1. 운영 주소에 접속합니다. 최신 Chrome·Edge·Safari를 권장합니다.
2. 첫 화면에서 **서울 → 부산 주행 시연** 또는 **서울역 → 서울시청 도보 시연**을 선택합니다.
3. 경로 결과에서 거리·소요시간·위험 표시를 확인한 후 **주행 시연 시작 / 도보 시연 시작**을 누릅니다.
4. 이동 중 위험 카드·위험 위치 아이콘·진행률을 확인합니다. **다음 위험**, 일시정지·재생, 종료 버튼을 사용할 수 있습니다.
5. **현재 레이더** 옆 **판단 근거**에서 설명과 판정 근거를 확인합니다. 팝업을 닫으면 해당 음성도 중단합니다.

이 시연은 실제 경로와 가상 위험 이벤트를 구분해 표시합니다. 가상 강수·특보·노면·사고 이벤트를 공식 관측이나 실제 통행 위험으로 사용하지 않습니다. 길찾기 공급자가 응답하지 않으면 실제 경로가 필요한 시연도 제한됩니다.

### 더미 시나리오 평가

1. 첫 화면의 **더미 시연모드**를 엽니다.
2. 자동차·도보 모드와 출발지·목적지를 선택합니다.
3. 제공되는 시나리오를 선택해 실행하고 위험판정·안내·실행 기록을 비교합니다.
4. 더미 결과는 실제 자료 조회 결과와 구분합니다. 화면의 시연 안내를 확인합니다.

### 실제 경로와 GPS

1. 자동차 또는 도보를 선택하고 출발지·목적지를 검색·선택합니다.
2. 출발 예정시각을 정하고 **경로 살펴보기**를 누릅니다.
3. 경로와 자료의 수신 상태를 확인하고 안내를 시작합니다.
4. 실제 위치 추적은 브라우저 위치 권한이 필요합니다. 화면을 켜둡니다.
5. 조작과 시험은 정차한 상태에서 수행합니다. 제공 경로는 실제 통행 안전을 보증하지 않습니다.

### 모델 교체와 장애 대체

1. **설정 → LLM 상황 브리핑·근거 설명**을 엽니다.
2. **Google Gemini** 또는 **GPT-OSS**를 선택하고 **선택한 모델 적용**을 누릅니다. 운영자가 저장한 키는 화면에 노출하지 않습니다.
3. 같은 경로·같은 시연 시점에서 **판단 근거**를 요청합니다.
4. 모델명, 설명 출처, 근거와 실제 모델 응답 검증 여부를 확인합니다. 모델 선택이나 키 등록만으로 성공을 판정하지 않습니다.
5. 다른 모델로 바꾸어 같은 조건으로 비교합니다. 외부 API 상태·호출 한도에 따라 정형 설명으로 대체될 수 있습니다.
6. **LLM 미사용 · 정형 설명**을 적용해도 위험판정·경로·기본 안내가 동작하는지 확인합니다.

심사 증빙은 실제 모델 응답 검증 완료 화면·모델 ID·시험시각·동일 시나리오 조건을 함께 기록합니다. 코드 계약시험만으로 두 외부 모델의 실시간 정상 구동을 입증한 것으로 보지 않습니다.

## 4. 위험판정과 LLM의 역할

- `public/risk-engine.mjs`: 규칙 기반 위험판정.
- `public/safe-route-engine.mjs`: 대안 경로 비교와 조치 결정.
- `lib/llm-explanation.mjs`: 모델 호출·응답 검증·정형 설명 대체.
- `lib/api.mjs`: 서버 전용 API 중계, 키와 세션 관리.
- `public/vector-driving.mjs`: 진행방향 지도 표시.

LLM은 엔진이 제공한 승인 근거 문장 ID의 선택·배열에 사용합니다. LLM이 위험등급이나 우회 결정을 새로 생성하는 구조가 아닙니다. 검증되지 않은 근거·조치 변경·필수 불확실성 문구 누락은 거절하고 정형 설명을 제공합니다. 설명 요청에는 필요한 판정 근거와 질문을 보내며 GPS 좌표·목적지·전체 경로 형상을 보내지 않습니다.

Gemini 어댑터와 OpenAI 호환 `/chat/completions` 어댑터를 분리해 특정 모델 의존성을 줄였습니다. GPT-OSS는 현재 Groq에서 제공하는 모델을 연결하는 설정이며, 다른 호환 서버는 관리자가 `LLM_CUSTOM_*`로 별도 등록합니다. 임의 URL을 일반 사용자에게 입력받지 않습니다.

## 5. 로컬 설치·실행 (Next.js)

Node.js **24.x**, pnpm **11.25.0**을 사용합니다. 인터넷 연결과 필요한 외부 API 이용권한이 필요합니다.

```bash
npm install --global pnpm@11.25.0
pnpm install --frozen-lockfile
```

`.env.example`을 `.env.local`로 복사하고 개인 개발 환경의 값만 입력합니다. macOS/Linux는 `cp .env.example .env.local`, Windows PowerShell은 `Copy-Item .env.example .env.local`을 사용합니다. `SESSION_SECRET`은 아래 명령으로 생성한 새 값을 직접 입력합니다.

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
pnpm exec next dev --webpack --hostname 127.0.0.1 --port 3000
```

브라우저에서 **http://127.0.0.1:3000**에 접속합니다. `.env.local`의 `APP_ORIGIN`도 정확히 `http://127.0.0.1:3000`으로 맞춥니다. `localhost`와 `127.0.0.1`을 섞으면 Origin 검사가 실패할 수 있습니다. 외부 기기에서 사용할 때에는 HTTPS 배포와 해당 도메인 설정이 필요합니다.

로컬 배포형 빌드:

```bash
pnpm check
pnpm test
pnpm build:vercel
pnpm exec next start --hostname 127.0.0.1 --port 3000
```

이 안내는 현재 Vercel 운영과 같은 Next.js 실행 경로입니다. 기존 `pnpm dev`, `pnpm build`, `pnpm start`에는 별도 관리형 환경용 설정이 포함되어 있으므로 위 명령을 사용합니다. 의존성을 설치하지 않은 상태에서는 `h5wasm` 관련 시험 등이 실패할 수 있습니다.

## 6. 환경변수

모든 실제 키는 `.env.local` 또는 배포 플랫폼의 비밀 환경변수에만 저장합니다. 제출 ZIP·GitLab·README에 실제 키나 `.git` 이력을 포함하지 않습니다.

| 이름 | 용도 |
| --- | --- |
| `APP_ORIGIN` | 접속 주소와 정확히 일치하는 origin |
| `SESSION_SECRET` | 최소 43자 세션 암호화용 비밀값 |
| `KAKAO_REST_API_KEY`, `KAKAO_JAVASCRIPT_KEY` | 장소 검색·자동차 경로·지도; 허용 도메인 별도 등록 |
| `TMAP_API_KEY` | 도보 경로 |
| `KMA_API_KEY` | 기상청 예보·레이더·위성·도로기상 어댑터 |
| `ROAD_API_KEY`, `KOROAD_API_KEY` | ITS 교통·TAAS 보행 관련 어댑터 |
| `SAFETYDATA_API_KEY`, `SAFEMAP_API_KEY`, `DATA_GO_KR_API_KEY` | 재난·안전·공공자료 관련 설정 |
| `VWORLD_API_KEY` | 선택적인 위성 배경지도 |
| `GEMINI_API_KEY`, `LLM_GEMINI_MODEL` | Google Gemini 서버 저장 연결 |
| `LLM_PROVIDER`, `LLM_MODEL`, `LLM_BASE_URL`, `LLM_API_KEY` | GPT-OSS 등 기본 호환 API 연결 |
| `LLM_CUSTOM_MODEL`, `LLM_CUSTOM_BASE_URL`, `LLM_CUSTOM_API_KEY` | 별도 호환 모델 서버 |

미설정 자료는 결측·미연결로 표시합니다. LLM 키 없이도 정형 근거 설명을 사용할 수 있으나 실제 길찾기·지도에는 해당 공급자의 키가 필요합니다. 선택적인 Google 음성 키는 앱의 음성 연결에서 따로 관리합니다.

## 7. 검증 범위와 제한

- 기준 앱 커밋의 GitHub 자동시험과 Vercel 빌드 성공을 확인했습니다.
- 지도·GPS·주행 안내·LLM 관련 선택 시험 35개가 통과했습니다. 계약시험에는 모의 응답이 포함되므로 외부 API 실시간 수신 성공과 구분합니다.
- 운영에서 도보 경로 조회·시연 안내 시작·저장된 LLM 설정 표시를 확인했습니다.
- 진행방향 지도는 WebGL 지원이 필요합니다. 시험용 브라우저에서는 그래픽 기능이 비활성화되어 기본 지도 대체를 확인했으며, 실제 지도 회전은 지원 기기에서 추가 검증이 필요합니다.
- 브라우저 한국어 음성·마이크는 기기 지원과 권한에 영향을 받습니다. 시험 환경의 음성 합성 실패를 실제 발화 성공으로 기록하지 않습니다.
- PWA는 화면 닫힘·잠금·백그라운드에서 연속 위치 추적이나 음성 안내를 보장하지 않습니다.
- 예보·레이더·과거 통계는 현장 실측 및 통행 안전 보증이 아닙니다. 표본 사이의 모든 위험을 탐지하지는 못합니다.

## 8. 공공 GitLab 제출 설정

1. 가입한 공공 GitLab에서 비공개(Private) 프로젝트를 생성합니다.
2. 제출본의 소스를 프로젝트 루트에 등록합니다. `README.md`, `package.json`, `pnpm-lock.yaml`, `app`, `public`, `lib`가 루트에 있어야 합니다. ZIP 하나만 올리고 소스를 누락하지 않습니다.
3. 프로젝트 설정 → 일반 → Topics에서 **2026 공공 AI 대전환 챌린지 세션1**을 선택합니다.
4. 심사위원 열람 권한은 주최 측 안내에 따라 부여합니다. 비공개 설정만으로 심사위원 권한이 자동 부여되었다고 간주하지 않습니다.
5. 참가신청서에는 운영 주소와 별도로 **공공 GitLab 프로젝트 주소**를 기재합니다.
6. GitLab 등록 이후 소스와 실행 주소의 버전이 달라지지 않도록 제출 버전을 관리합니다.

개발 중 문서와 과거 검증 기록은 `docs/`에 보관했습니다. 날짜별 기록은 당시 상태이며 최신 실행 방법과 제출 범위는 이 README를 기준으로 합니다. `SETUP.md`는 초기 개발 환경의 기록이므로 현재 Next.js 실행은 위 절차를 따릅니다.
